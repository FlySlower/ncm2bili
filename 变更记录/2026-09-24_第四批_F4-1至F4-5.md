## 五、F4-5 纯重构人工抽查说明

逐 hunk 人工核对 fav.py / main.py / config.yaml  diff，确认行为不变点：

1. `matched_song_ordinals()`：SQL 字符串、参数、排序、状态集合（DONE/MATCHED/FAV_FAILED + bvid IS NOT NULL）与 fav_songs 原内联查询逐字一致，仅从函数内闭包搬为 BiliFavClient 公开方法（self._db 与原传入 db 同为 cache.db 同一实例）。
2. `slowdown_multiplier` property 仅返回 `self._slowdown_multiplier`，worker 计算公式（base × slowdown / concurrency_multiplier）未变。
3. `fav_one` 删除手动 UPDATE：依赖 F3-2 已落地的 upsert_song 语义（status=DONE 时 fail_reason 强制 None，db.py 白名单），第三批已有用例 `test_gate_reject_clears_legacy_bvid_then_done_clears_reason` 锁定该行为，本批全量测试复跑通过。
4. `if code == 0 or code in ALREADY_IN_FOLDER_CODES` → `if code == 0`：集合元素仅 {0}，布尔结果完全等价。
5. `ensure_folders(total=0)`：旧逻辑建 1 个空夹（list+add 两请求），新逻辑零请求返回 []；fav_songs 仅在 `total_matched or len(songs)` 为正时才需要 media_ids，全空时 assigned 为空、无 worker，不产生越界——新用例与全量集成测试共同锁定。
6. main.py `manual_cnt` 改名仅局部统计变量，stats 字典键名 "manual" 不变；docstring/description/config.yaml 仅注释文案。
