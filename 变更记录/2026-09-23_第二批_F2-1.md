## 一、修复的缺陷（为什么改）

正式运行阶段三被中断时（如 -101 凭证失效、-400 建夹失败、进程被杀），"已匹配未收藏"的歌
在旧语义下已经是 DONE；resume 只重试 FAV_FAILED，这些歌**永久漏收藏**且任务显示完成。
本批按文档语义重建状态流：**匹配成功 ≠ 收藏完成**，仅 fav_one() 收藏成功才写 DONE。

## 五、状态机新旧语义对照

| 场景 | 旧语义（v0.4.2/3） | 新语义（v0.4.4 F2-1） |
| --- | --- | --- |
| 匹配成功（正式运行） | 直接写 DONE（bvid 已定） | 写 **MATCHED**（method 不变），bvid 已定；等阶段三 |
| 匹配成功（dry-run） | DONE | DONE（不变，§10.1 例外） |
| fav_one 收藏成功 | DONE（幂等重写） | DONE（唯一写入点，不变） |
| deal 已收藏（code 0/62002） | DONE | DONE（不变） |
| deal 视频失效（-404） | MANUAL | MANUAL（不变） |
| deal 其他失败 | FAV_FAILED | FAV_FAILED（不变） |
| 阶段二后任务状态 | 任务即 DONE | **保持 RUNNING**，阶段三完成后才 DONE；dry-run 阶段二完成即 DONE |
| 阶段三中断后 resume | 只重试 FAV_FAILED；已"DONE"未收藏的歌**永久漏收藏**、任务显示完成 | 阶段二跳过 DONE/MATCHED/FAV_FAILED（不回搜索）；阶段三对 MATCHED 首次收藏、FAV_FAILED 重试收藏，deal 次数=未完成数 |
| manual 重查升级 DONE 歌 | 直接改 DONE 的 bvid/method（无后续动作） | 正式运行置 MATCHED+MANUAL 交阶段三收藏新 BV；dry-run 保持 DONE |
| 老库（全 DONE）迁移 | 无 | 打开即全量转 MATCHED（一次性标记），阶段三补收藏，deal 幂等 |
| DONE 的含义 | 匹配完成（可能未收藏） | **收藏完成**（仅 dry-run 下=匹配完成） |
